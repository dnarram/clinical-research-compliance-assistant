# Brief and rubric → where each requirement is met

Every requirement of the assignment ("Asistente Experto con Gemini, RAG y Agentes", Evolve,
Generative AI module) with the evidence in this repository. Notebook sections refer to
[`notebooks/compliance_assistant.ipynb`](../notebooks/compliance_assistant.ipynb).

## Technology stack (mandatory)

| Required | Used | Where |
|---|---|---|
| LLM and embeddings: Google Gemini | `gemini-3.5-flash-lite` (answers, rewrites), `gemini-embedding-2` (768 d) | `src/compliance_assistant/config.py`, `agent.make_llm`, `vectorstore.get_embeddings` |
| Vector knowledge base: ChromaDB | `langchain-chroma` over a persisted Chroma collection (cosine) | `vectorstore.rebuild_chroma`, `build_or_load` |
| Agent framework: LangGraph on LangChain | explicit `StateGraph` + `InMemorySaver` checkpointer | `graph.build_graph`, notebook §6 |
| Environment: Jupyter or Colab | Jupyter notebook, Colab-ready first cell | notebook §1 |
| (Optional) Streamlit | `app.py`, deployed on Streamlit Cloud | README *Live demo* |

## Step-by-step instructions

| Step | Evidence |
|---|---|
| 1 · Define the expert's topic; ≥ 3 substantial documents | README *Why this domain*; `data/kb/sources.yaml` |
| 2 · Load documents into ChromaDB; preprocess (cleaning, chunking, noise removal) | `ingestion.py` (header/footer, hyphenation, TOC removal; section-aware chunks); notebook §2.1 shows raw vs clean |
| 2 · Verify the collection answers test queries **before** connecting the agent | notebook §4 and `scripts/02_sanity_retrieval.py` (EN/ES pairs, out-of-domain, calibrated threshold) |
| 3 · Define role, tone, limitations and behaviour without enough information | `SYSTEM_V4` sections GROUNDING, SCOPE AND TONE, graded insufficiency; `refuse` node |
| 3 · Document the prompt in the README with a justification | README *System prompt and its justification* (full text + clause-by-clause table) |
| 4 · LangGraph graph: receive question, retrieve from ChromaDB, answer with Gemini | `graph.py`; diagram in notebook §6 and [`architecture.md`](architecture.md) |
| 4 · Ensure the knowledge base is used on every query | explicit graph — every turn goes through `retrieve`; invariant 6 in `CLAUDE.md` |
| 5 · Memory of previous questions, coherence across the conversation | notebook §7 (referential follow-up, "summarise what you told me", thread isolation) |
| 5 · At least one notebook example proving memory (question referring to an earlier answer) | notebook §7 turn 2 and turn 3; §10 second turn ("¿…esos documentos?") |
| 6 · Interactive cell to talk to the agent with immediate answers | notebook §10 |
| 6 · ≥ 5 example questions with documented answers | notebook §8 (6 questions with expected-answer notes); README *Example conversations* |
| 7 (optional) · Streamlit interface, deployed on Streamlit Cloud | `app.py`; public URL in the README |

## Advice in the brief

| Advice | Followed |
|---|---|
| API key in an environment variable or `.env`, never in code | `.env` (git-ignored), Streamlit/Colab secrets; pre-commit hook rejects key-like strings |
| Start with a small dataset before scaling | first build with ICH E2A only (12 pages), then E6(R3) and Helsinki — `decisions.md` |
| Iterate on the system prompt | v1 → v4, each with its observed failure — `prompt_iterations.md` |
| Use LangGraph tracing to debug the agent | `stream_mode="updates"` node-by-node trace (notebook §6.1); per-node log lines |
| Document technical decisions while developing | [`decisions.md`](decisions.md), dated entries |
