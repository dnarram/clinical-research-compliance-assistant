The system prompt: three versions, each fixing a real failure

v1 · class baseline

“Answer from the documents”

  • Fluent but unattributed: 7 days and 15 days with no source
  • Answered 21 CFR Part 50 from general knowledge, with invented citations
  • Register drifts (“Sure! Here’s a quick overview…”)

v2 · role and scope

Audience, grounding, “I could not find this”

  • Invented citations stopped; off-topic questions declined
  • Still merged E6(R3) and Helsinki into one claim
  • Spanish questions answered in English half the time

v3 · in use

Citation protocol, differing sources, language policy, format

  • Every factual sentence carries [n]; regulatory wording quoted verbatim in English
  • When E6(R3) and Helsinki differ, each position is attributed
  • Answer in the user’s language; SAE, SUSAR, IB, IMP untranslated

Hard constraints in code, judgement in the prompt. An English question once came back in Spanish despite the rule, so the user message now carries a deterministic “Reply in English / Responde en español” line, and out-of-domain questions never reach the model at all.

Full prompt and rationale: README · docs/prompt_iterations.md

The prompt went through three versions. Version one is the bare class prompt: fluent, unattributed, and it answered a question about an FDA regulation we do not index, with made-up citations. Version two added role, scope and the insufficiency rule, but still merged sources and sometimes ignored the language. Version three adds the citation protocol, differing-source handling, the language policy and the output format. One lesson: hard constraints belong in code.
