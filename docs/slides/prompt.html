The system prompt: three versions, each fixing a real failure

v1 · class baseline

“Answer from the documents”

  • Observed: correct and fluent, but no citation markers — a CRA cannot tell which passage supports which sentence
  • No rule for missing information: nothing stops it completing from general knowledge
  • No role, no scope, no language policy

v2 · role and scope

Audience, grounding, “I could not find this”

  • Adds the audience, the grounding rule and the refusal wording
  • Still no per-sentence traceability — only a trailing sources list
  • No rule for documents that disagree; no language policy for Spanish questions

v3 · in use

Citation protocol, differing sources, language policy, format

  • Every factual sentence carries [n]; regulatory wording quoted verbatim in English
  • When E6(R3) and Helsinki differ, each position is attributed
  • Answer in the user’s language; SAE, SUSAR, IB, IMP untranslated

Hard constraints in code, judgement in the prompt. An English question once came back in Spanish despite the rule, so the user message now carries a deterministic “Reply in English / Responde en español” line, and out-of-domain questions never reach the model at all.

Full prompt and rationale: README · docs/prompt_iterations.md

The prompt went through three versions. Version one is the bare class prompt: on the SUSAR question it was correct and fluent but carried no citation markers, so nothing tells you which passage supports which sentence, and it has no rule for missing information. Version two added role, scope and the refusal wording — a design step, still without per-sentence traceability. Version three adds the citation protocol, differing-source handling, the language policy and the output format; on the live model it cited every sentence, contrasted E6(R3) with Helsinki, and said plainly that 21 CFR Part 50 is not in its sources. One lesson: hard constraints belong in code.
